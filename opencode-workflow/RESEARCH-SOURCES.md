## Design evidence and limits

| Source | Relevant lesson | How it applies here |
|---|---|---|
| [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents) (2024) | Prefer simple, composable patterns; add orchestration when it improves results, because it costs latency and tokens. | `WORKFLOW.md` and `opencode/agent/deep.md` use selective delegation rather than compulsory fan-out. |
| [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (2025) and [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/) (2026) | Keep always-loaded instructions small; retrieve task-specific material when needed. Encode repeated architecture rules as checks, not more prompt text. | `WORKFLOW.md` stays a short map. Placement rules live in `principle-extend-the-existing-home`, which is markdown only. A familiar one-file change skips that search. |
| [Thoughtworks: Engineering the harness](https://www.thoughtworks.com/en-us/insights/blog/architecture/engineering-the-harness-a-practical-pattern-for-reliable-coding-agents) (2026) | Guides steer before the agent acts. Sensors check after. A rule the agent keeps breaking should become a linter or test, with the fix named in the failure. | Placement stays in `principle-extend-the-existing-home`. A UI file does not import the database. An API route or `src/routes` file may. A repo-local test is the follow-up when the same miss repeats. |
| [Anthropic: Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps) (2026) | Separate planning from generation and evaluation. Drop scaffolding once it no longer changes behavior. | Feature step 2 writes the user action, data shape, owning layer, and proof command before the first edit. Poteto-mode opens a principle only when its when-line matches. |
| [OpenAI: Agent skills](https://developers.openai.com/codex/skills) and [Using skills to accelerate OSS maintenance](https://developers.openai.com/blog/skills-agents-sdk.md) (2026) | Keep the deterministic step in a script. Load a skill from its description instead of pasting it into every session. | `fetch-sources.mjs` accepts at most three https URLs. `frontend-ui` loads for UI files and is not injected by `WORKFLOW.md`. The research agent may run only that fetch script, and the parent passes its absolute path. Placement itself stays a markdown skill. |
| [Cursor: Best practices for coding with agents](https://cursor.com/blog/agent-best-practices) (2026) and [Cursor subagents](https://cursor.com/docs/agent/subagents) | Plan uncertain work; separate context-heavy investigations, but skip ceremony and subagents on small tasks. Scope file-specific guidance so it stays out of unrelated turns. | `deep` may implement cohesive tasks locally; delegate only when isolation, independent work, or expertise pays off. A familiar one-file change skips the home search. |
| [Cursor: Scaling long-running autonomous coding](https://cursor.com/blog/scaling-agents) (2026) | Planner/worker coordination helped unusually large experiments; flat shared-state coordination suffered contention. | One-hop leaves and disjoint write ownership are sensible guardrails, not a reason to spawn workers for every task. |
| [Anthropic: Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (2025) | Long tasks need resumable progress and verified completion beyond context compaction alone. | `principle-sequence-verifiable-units` appends `docs/agent-progress.md` only when a later session will continue the work. A unit that finishes in the current session does not add that file. |
| [Cursor: Agent sandboxing](https://cursor.com/blog/agent-sandboxing) (2026) | Approve-every-command causes interruptions and approval fatigue; sandboxing reduces prompts in Cursor's environment. | This plugin asks before coding-agent shell commands but does **not** provide a sandbox. Cursor's reported gains are not measurements of OpenCode or this repository. |
| [OpenAI: Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals) and [LangSmith: Evaluation concepts](https://docs.langchain.com/langsmith/evaluation-concepts) | Inspect traces for routing mistakes, then compare changes against curated tasks and outcomes. | `scripts/install.test.mjs` tests wiring, not quality/cost. Before claiming savings, compare `pure` and routed runs on the same representative tasks, recording accepted outcome, time, cost, rework, and test results. |

## Continued pass (public sources through late 2026)

These are newer than the rows above. Their benchmark numbers belong to those papers and products. They are not measurements of this plugin.

| Source | Relevant lesson | How it applies here |
|---|---|---|
| [Fowler: Harness engineering for coding agent users](https://martinfowler.com/articles/harness-engineering.html) | Split controls into computational sensors (tests, linters, type checks) and inferential sensors (model review). Run the cheap deterministic ones on every change. | The repo's own tests are the computational sensors. `/review` and thermos stay inferential and optional. Do not add another model review to the default loop. |
| [Harness anatomy of eleven coding systems](https://arxiv.org/html/2609.00006), including OpenCode | Production harnesses favor a hand-written loop and deterministic retrieval. Generic subagents and heavy context compression are the parts that vary, not the edit loop. | Keep `code` as the default loop. `research`, `worker`, and `expert` stay task-specific leaves. Do not add a general-purpose child. Read the OpenCode section of that paper before copying another vendor's orchestration. |
| [Beyond the model: harness effects](https://arxiv.org/html/2609.32459) (2026-09-26) | On localized repairs, extra harness complexity mostly helps weaker models. Structured tools and task-specific subagents are the stable gains. Context compression and generic subagents can hurt open-ended repository work. Lazy skills help. | Do not grow `WORKFLOW.md` to chase a benchmark. Load skills when the description matches. Compact a session only by starting fresh with `docs/agent-progress.md`, not by summarizing the whole transcript into the next prompt. |
| [Anthropic: Managed agents](https://www.anthropic.com/engineering/managed-agents) | Harness assumptions go stale as models change. A failed execution environment is a tool error the agent can retry. Do not preserve a broken session just to keep its context. | Question a rule again when a model stops violating it. A hung or failed command stays evidence. One identical retry only for a concrete transient cause, which `WORKFLOW.md` already says. |
| [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | An eval measures the model and the harness together. Each trial starts clean. Leftover git history from a previous trial is leakage. | A future behavior eval of placement must start from a clean directory. Do not grade this plugin from a transcript that can see an earlier attempt. |
| [OpenAI: AGENTS.md](https://developers.openai.com/codex/guides/agents-md) | Project instructions are discovered from the work directory upward, concatenated, and capped (32 KiB in Codex). Closer files override earlier ones. | Keep project `AGENTS.md` a map. This plugin does not write that file except through `/learn`, and it does not replace a closer project file with `WORKFLOW.md`. |
| [Cursor hooks](https://cursor.com/docs/hooks) | A post-edit or stop hook can run a deterministic check and block, which is stronger than asking the model to remember the script. | OpenCode V2's plugin hook used here is `context` only. It cannot see a file write. Placement stays the markdown skill. |
| [VERSE](https://arxiv.org/html/2610.02616) and [Agentic harness engineering](https://arxiv.org/abs/2604.25850) | Automatic harness edits need a replay of the failure and a check that the edit does not regress other tasks. Gains in those papers are not portable. | A prompt or skill change here is promoted only after `verify-opencode.mjs` still passes, plus a fresh task that used to fail. Do not copy their reported percentages onto this plugin. |

## Evidence status

- **Verified locally:** Node installation tests and `scripts/verify-opencode.mjs` check package assets and a mocked hook; `scripts/check-host.mjs` reports host/config drift without changing user files.
- **Observed, not an automated test:** On 2026-10-12 a local OpenCode 2.0.26 `plugin update` moved `opencode-pstack` to the pushed commit and copied skills into the user config. That does not prove permission enforcement or that a `pure` session skips the bundled workflow.
- **Not yet verified:** Effective V2 permissions in a running session, workflow exclusion for `pure`, and any controlled task replay or measured cost reduction.
- **Do not generalize vendor or paper metrics:** Cursor's sandbox and swarm results, Anthropic's multi-agent results, and the percentage-point gains in the September 2026 harness papers come from their own environments, models, and workloads. Use them to formulate tests, not to predict savings for this plugin.
